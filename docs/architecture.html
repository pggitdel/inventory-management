Factory Inventory Management System

Architecture overview: system layout, tech stack, and data flow

System Architecture

Frontend

Vue 3 + Vite, port 3000
  • 7 views: Dashboard, Inventory, Orders, Demand, Spending, Reports, Backlog
  • Vue Router (6 routes; Backlog is a Dashboard sub-view)
  • Shared filter state: useFilters.js
  • i18n (en, ja), auth composable, detail modals
→HTTP / JSON
axios

Backend API

FastAPI + Uvicorn, port 8001
  • main.py: routes, filtering, aggregation
  • Pydantic models validate responses
  • CORS open to all origins
  • Auto docs at /docs
→import at
startup

Data

In-memory, no database
  • mock_data.py loads JSON once on import
  • 7 files in server/data/
  • generate_data.py regenerates the data

Data Flow

  1. User changes a filter (Time Period, Warehouse, Category, Order Status). State lives in the singleton refs in useFilters.js, shared by all views.
  2. View calls client/src/api.js, which builds query params (skipping "all") and sends an axios GET to localhost:8001/api.
  3. FastAPI route handles the request and filters the in-memory lists with apply_filters / filter_by_month.
  4. Pydantic validates the result against the response model and returns JSON.
  5. View stores raw data in refs (allOrders, inventoryItems); computed properties derive the charts, totals, and tables that render.

Notes

Known gap: api.js defines POST /tasks and POST /purchase-orders calls, and main.py defines a CreatePurchaseOrderRequest model, but the backend has no POST routes. Those calls would return 404 today. Also, inventory filters do not support month (inventory has no time dimension), and all data resets on server restart.
